# Hydro-Hitch: old vs new

Open index.html for seven side-by-side screen comparisons and an interactive image viewer.

Old images: unchanged screenshots extracted from the original project report. New images: actual local application captures. Different dates/datasets; no numerical performance claim is inferred from screenshots.

| Area               | Old                                                                                                            | New                                                                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Frontend           | CRA customer app plus a separate Vite admin/vendor app; React 18, mixed MUI/Ant/other UI packages.             | One React 19 + Vite application with lazy routes, shared CSS/components and role-aware navigation.                                                          |
| API stack          | Express 4, Mongoose 8, CommonJS and multiple legacy route files.                                               | Express 5, Mongoose 9, ESM modular API at /api/v2; strict Zod input contracts.                                                                              |
| Authentication     | JWT/raw token handling; user middleware could continue on absent or invalid authentication.                    | Opaque session tokens stored hashed in MongoDB, HttpOnly cookies, expiry, revocation and account-state checks.                                              |
| Authorization      | Several operations trusted supplied customer/vendor identifiers; missing checks on privileged paths.           | Endpoint roles and record ownership enforced on the server; public registration cannot grant an operations role.                                            |
| Order states       | pending → process → completed; update controller accepted any of the three valid values.                       | PENDING → CONFIRMED → ASSIGNED → EN_ROUTE → ARRIVED → DELIVERING → DELIVERED, with restricted CANCELLED/FAILED paths.                                       |
| Dispatch integrity | No equivalent dedicated driver/tanker slot-reservation model in the audited v1 order flow.                     | Transactions, unique reservations, capacity and availability checks; simultaneous conflicting assignments rejected.                                         |
| Pricing            | Client distance calculation, vendor per-km fee and submitted Price.                                            | Central capacity/water/priority/service/promo/tax calculation, immutable price snapshot and quote revision check.                                           |
| Payments           | Order Price/status fields; no comparable audited cash ledger.                                                  | Explicit administrator cash collection and full refunds with duplicate protection. Online/bank payments remain disabled.                                    |
| Reviews            | Vendor-level review flow.                                                                                      | One review per delivered booking with ownership and duplicate checks.                                                                                       |
| Data migration     | Original users, vendors, products and orders in v1 collections.                                                | Separate v2_ collections; read-only migration preview; explicit repeat-safe imports; old password hashes not reused. Vendor/product mapping remains manual. |
| Repository secrets | Committed environment files and inline credentials existed in old history.                                     | Both published branches now begin at a clean root; .env and runtime files ignored. Provider revocation/cached copies remain separate responsibilities.      |
| Dependency audit   | Recorded separate audits: server 17 findings, client 67, admin 27. Counts may overlap across dependency trees. | Recorded retrofit audit: zero findings. This is a checkpoint, not a permanent guarantee.                                                                    |
| Verification       | No comparable executable end-to-end test suite found in the original audit.                                    | Recorded 26 API/unit/migration and 5 browser/accessibility tests passed; production build/smoke, lint and formatting passed.                                |
| Deployment         | Separate app configuration and multiple package locks.                                                         | npm workspace/one lockfile, CI, Dockerfile, Compose and deployment runbook. Docker runtime verification remains outstanding.                                |

Important gap: independent vendor self-service and distance-based delivery pricing are not retained. GPS, online payments, SMS/push and production rollout remain incomplete.

Public edition: the archived checkout screenshot containing a personal account name is withheld. Six other archived interface screenshots are paired with actual v2 captures.
